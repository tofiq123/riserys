# Localization (l10n)

This app has **localization infrastructure only** wired up. The delegates and a
generated `AppLocalizations` class exist and are attached to the root
`MaterialApp`, but the existing UI still uses hardcoded English strings.

**Migrating those strings to `AppLocalizations.of(context)` is an ongoing
follow-up** — done incrementally, screen by screen, so widget tests that pump a
screen without the localization delegates keep passing. Do not do a bulk
find-and-replace.

## How it's wired

- `pubspec.yaml`: `flutter_localizations` (sdk) + `intl`, and `flutter: generate: true`.
- `l10n.yaml`: points the generator at `lib/l10n/`.
- `lib/l10n/app_en.arb`: the English template (source of truth for keys).
- `lib/l10n/app_localizations*.dart`: **generated** by `flutter gen-l10n`
  (also regenerated automatically on `flutter pub get` / build because
  `generate: true` is set).
- `lib/main.dart`: the root `MaterialApp` sets
  `AppLocalizations.localizationsDelegates` (which includes the global
  Material/Widgets/Cupertino delegates) and `AppLocalizations.supportedLocales`.

## Adding a string

1. Add the key + `@key` description block to `lib/l10n/app_en.arb`, e.g.

   ```json
   "createAlarm": "Create alarm",
   "@createAlarm": { "description": "Title of the create-alarm screen." }
   ```

2. Run `flutter gen-l10n` (or just `flutter pub get`) to regenerate.
3. Use it in a widget: `AppLocalizations.of(context)!.createAlarm`.

## Adding a language

Add `lib/l10n/app_<locale>.arb` (e.g. `app_es.arb`) with the same keys
translated, then regenerate. The new locale is picked up automatically via
`AppLocalizations.supportedLocales`.

## Testing note

When a widget test pumps a screen that reads `AppLocalizations.of(context)`,
give the pumped `MaterialApp`/`WidgetsApp` the delegates:

```dart
MaterialApp(
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  supportedLocales: AppLocalizations.supportedLocales,
  home: ...,
)
```

Screens that still use hardcoded strings need no such change — which is why the
migration is incremental.
