# Phase 4b — Snooze budget + wake-up check — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a configurable snooze budget (shrinking durations, then a mission) and a "still up?" wake-up check that re-fires the alarm if the user falls back asleep after dismissing.

**Architecture:** Snooze rides the existing reconcile/`setAlarmClock` path via a new `snoozedUntil` on the alarm (no parallel scheduler). The wake-up check is OS-scheduled on Android (`AlarmManager`): a "Still up?" notification with an "I'm up" action, escalating to a re-fire through the existing ring path. Both timings are user-configurable in a new Settings screen backed by SharedPreferences.

**Tech Stack:** Flutter 3.35 / Dart 3.9, Drift SQLite, flutter_riverpod 2.6.1, Pigeon (Dart↔Kotlin), Android Kotlin (AlarmManager + notifications), shadcn "Mono" design system.

## Global Constraints

- `flutter_riverpod` pinned **2.6.1** — 2.x API only.
- **Local only.** No cloud/auth. Wake-check native is **Android-only** for now; the Pigeon contract is extended and the generated Swift protocol grows the methods, but there is **no Swift impl work** (the iOS engine is a later plan) — do not attempt to build/run iOS.
- **Drift:** `schemaVersion` → **4**; migration idempotent + multi-isolate-safe (check sqlite schema before DDL), same pattern as v2/v3. Generated `database.g.dart` is gitignored (regenerated by build_runner) — never commit it.
- **Snooze rides reconcile:** a future `alarm.snoozedUntil` makes `nextOccurrence` fire at it; snoozing never introduces a second scheduler. All timestamps UTC; wall-clock/day reasoning stays in Dart.
- **Wake-check is best-effort + degrades honestly:** if notifications are off, the "Still up?" prompt silently won't show but the re-fire (a full alarm) still fires. Scheduling/cancel failures are logged, never thrown into the ring/dismiss path.
- **Snooze budget:** default max **3**, shrinking sequence `[9, 5, 3, 2, 1]` min (take first N), or a flat user-chosen minutes. Past the budget the Snooze button hides. `maxCount == 0` disables snooze.
- **Wake-check:** default **on**, delay default **5 min** (configurable 1–30); fixed **100 s** response window.
- **Design tokens only** (`RiseColors`/`RiseSpacing`/`RiseRadii`/`RiseText`). **TDD, teeth-first.** `pump` (not `pumpAndSettle`) around the ring screen's animation. Preserve the device-validated dismissal ordering (`stopRinging` first, unconditional).

Add to `test/domain/alarm_test.dart` (inside `main()`):

```dart
  test('snoozedUntil round-trips and clears via the sentinel', () {
    const a = Alarm(id: 1, hour: 6, minute: 30);
    expect(a.snoozedUntil, isNull);
    final snoozed = a.copyWith(snoozedUntil: DateTime.utc(2026, 7, 20, 6, 39));
    expect(snoozed.snoozedUntil, DateTime.utc(2026, 7, 20, 6, 39));
    // Sentinel clears it back to null (plain copyWith can't express "set null").
    expect(snoozed.copyWith(clearSnoozedUntil: true).snoozedUntil, isNull);
    // copyWith without the flag preserves it.
    expect(snoozed.copyWith(label: 'x').snoozedUntil, DateTime.utc(2026, 7, 20, 6, 39));
  });

  test('equality treats the same snooze instant across UTC/local as equal', () {
    final a = const Alarm(id: 1, hour: 6, minute: 30)
        .copyWith(snoozedUntil: DateTime.utc(2026, 7, 20, 6, 39));
    final b = const Alarm(id: 1, hour: 6, minute: 30)
        .copyWith(snoozedUntil: DateTime.utc(2026, 7, 20, 6, 39).toLocal());
    expect(a, b);
    expect(a.hashCode, b.hashCode);
  });
```

Add to `test/domain/schedule_math_test.dart` (inside `main()`; it already sets up `tz` — reuse its existing location/helpers, mirroring the other `nextOccurrence` tests in that file):

```dart
  test('nextOccurrence fires at a future snoozedUntil, overriding the schedule', () {
    final loc = tz.getLocation('UTC');
    final from = tz.TZDateTime.utc(2026, 7, 20, 6, 30); // ringing now
    final alarm = const Alarm(id: 1, hour: 6, minute: 30, days: {1, 2, 3, 4, 5})
        .copyWith(snoozedUntil: DateTime.utc(2026, 7, 20, 6, 39));
    final next = nextOccurrence(alarm: alarm, from: from, location: loc);
    expect(next, tz.TZDateTime.utc(2026, 7, 20, 6, 39));
  });

  test('a past snoozedUntil is ignored (the snooze has fired); normal schedule resumes', () {
    final loc = tz.getLocation('UTC');
    final from = tz.TZDateTime.utc(2026, 7, 20, 6, 40); // after the snooze fired
    final alarm = const Alarm(id: 1, hour: 6, minute: 30, days: {1})
        .copyWith(snoozedUntil: DateTime.utc(2026, 7, 20, 6, 39));
    final next = nextOccurrence(alarm: alarm, from: from, location: loc);
    // Monday 6:30 next week (2026-07-20 is a Monday), not the past snooze.
    expect(next, tz.TZDateTime.utc(2026, 7, 27, 6, 30));
  });
```

- [ ] **Step 4: Honor `snoozedUntil` in `nextOccurrence`**

In `lib/domain/schedule_math.dart`, `nextOccurrence`, right after the `if (!alarm.enabled) return null;` guard, add:

```dart
  // A snoozed alarm fires at snoozedUntil (a deferred re-ring of the current
  // firing), ahead of its normal schedule. A snoozedUntil in the past means the
  // snooze has already fired, so it is ignored and the normal schedule resumes.
  final snoozed = alarm.snoozedUntil;
  if (snoozed != null) {
    final at = tz.TZDateTime.from(snoozed, location);
    if (at.isAfter(from)) return at;
  }
```
